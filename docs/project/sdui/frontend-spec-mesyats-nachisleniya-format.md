# Формат поля даты — `props.dateFormat`

Дата: 16.08.2026. Бэкенд уже присылает ключ, менять его не нужно.
Первоисточник — `docs/project/sdui/frontend-spec-mesyats-nachisleniya-format.md`
в **репозитории бэка** (webbuh); здесь — фронтовая часть.

## 1. Задача

«Месяц начисления» показывал `12.08.2026` вместо `08.2026`. Это не косметика: в
1С день там ввести нельзя, а при проведении применяется начало месяца —
пользователь выбирал день, документ писал движения на первое число, и введённый
день молча терялся.

Контракт:

```json
{
  "id": "field.periodRegistratsii",
  "type": "DATE_FIELD",
  "props": {
    "label": "Месяц начисления",
    "dataType": "DATE",
    "dateFormat": "MM.yyyy"
  }
}
```

Ключ приходит по коду реквизита, поэтому задевает 20+ типов документов и колонки
табличных частей — реализовано в общем компоненте даты, а не точечно.

## 2. Реализация

`src/shared/ui/inputs/date-format-spec.ts` — разбор формата:

| `dateFormat`                 | точность | виды календаря     |
| ---------------------------- | -------- | ------------------ |
| `dd.MM.yyyy` (или ключа нет) | день     | год → месяц → день |
| `MM.yyyy`, `LLLL yyyy`       | месяц    | год → месяц        |
| `yyyy`                       | год      | год                |

Токены ищутся по буквам date-fns (`d`/`D` — день, `M`/`L` — месяц); литералы в
одинарных кавычках вырезаются до разбора, иначе «д» из `'дата'` включила бы
выбор дня.

`src/shared/ui/inputs/datetime-input.tsx` — общий компонент даты (его используют
и поле формы, и ячейка ТЧ). При наличии `dateFormat` пикер получает `format`,
`views` и `openTo`; **без ключа не передаётся ничего** — у всех прежних полей
остаются дефолты MUI, поведение не меняется.

Потребители: `DateFieldNode` (`node.props.dateFormat`) и ячейка ТЧ
(`TableCellEditor` → `DateCellEditor`, `col.props.dateFormat`). Формат действует
и в readonly-ячейке: редактора там нет, но показывать день так же неверно.

## 3. Что уходит на сервер

Формат значения не меняется — по-прежнему полная дата (`yyyy-MM-dd` для DATE).
Разряды мельче формата пикер берёт из текущего значения или сегодняшнего дня,
поэтому перед сериализацией значение приводится к началу периода
(`snapToGranularity`): выбран август 2026 → `2026-08-01`. Без этого шага дефект
воспроизводился бы ровно как раньше, только с правильной подписью на экране.

## 4. Проверка

«Замещение» → «Месяц начисления»: показывает `08.2026`, день недоступен, после
сохранения и переоткрытия значение то же.

Автотесты: `date-format-spec.test.ts` (таблица форматов, приведение к началу
периода), `datetime-input.test.tsx` (настоящий пикер: подпись `08.2026`, в
календаре вместо дней радиогруппа месяцев, выбор месяца отдаёт `2026-09-01`),
`date-field-node.test.tsx` и `table-cell-editor.test.tsx` (проводка ключа + показ
в readonly-ячейке).

## 5. Границы

Легаси-рендерер форм (`features/form-renderer/ui/table-cell-renderer.tsx`) не
трогали: он не SDUI и `props` с `/api/view` не получает. Списки документов и
read-only таблицы движений формат тоже не читают — там дата показывается своими
форматтерами, отдельная задача, если понадобится.
