# Условно обязательная ячейка ТЧ — `__requiredCells`

Дата: 15.08.2026. Бэкенд-часть реализована в webbuh.
Связанные: колоночный `props.required` (SCRUM-329), ADR-0011 (TABLE_COLUMN).

## 1. Проблема

Репорт: «не подсвечивается обязательное поле, которое становится обязательным
после определённого значения у Источника финансирования».

«Код платных услуг» обязателен не всегда, а только в строках, где «Источник
финансирования» = «Деньги от реализации государственными учреждениями товаров
(работ, услуг)». В 1С (`ПриемНаРаботу/Форма_ФормаДокумента.txt`) это два
механизма: сообщение, привязанное к ячейке через путь
`Начисления[N].КодПлатныхУслуг` (:329-345), и `УсловноеОформление` (:425-436),
делающее ту же ячейку `ТолькоПросмотр` в строках с другим источником.

До этой правки фронт показывал только тост: пользователь видел текст, но не
понимал, в какой строке и в каком поле проблема. Колоночный `props.required`
здесь не годится — он пометил бы колонку целиком, включая строки с бюджетным
источником.

## 2. Контракт бэка

Служебный ключ строки (не props узла) — массив кодов колонок, обязательных
именно в этой строке:

```json
{
  "rowId": "12345",
  "IstochnikFinansirovaniya": { "id": 501, "presentation": "Деньги от реализации..." },
  "KodPlatnykhUslug": null,
  "__requiredCells": ["KodPlatnykhUslug"]
}
```

- ключ ставится по источнику, а не по пустоте: заполненная ячейка остаётся
  помеченной (метка не мигает при вводе), смена источника — ключ снимается;
- строки с другим источником ключа не несут вовсе (не пустой массив);
- приходит в том же `setValue`-патче на ТЧ, что и остальные пересчитанные ячейки;
- поверх ключа сохраняется прежний тост-предупреждение — не блокирующий, как и
  в 1С (клиентская процедура без `Отказ`).

## 3. Реализация на фронте

Правило ячейки — `src/features/sdui/lib/utils/is-cell-required.ts`:

```ts
required = col.required || row.__requiredCells?.includes(col.binding)
```

Точки применения (обязательность считается на ЯЧЕЙКЕ, а не на колонке):

- `src/features/sdui/lib/utils/build-column-defs.ts` — плоская `TABLE_COLUMN` и
  под-колонки `COLUMN_GROUP orientation=VERTICAL` (сложная таблица);
- `src/features/sdui/ui/nodes/composite/editable-table.tsx` — простая таблица.

Дальше всё как у колоночного `required` (SCRUM-329): `RequiredCellFrame` —
красная рамка у пустой ячейки после blur либо сразу при `revealErrors`
(после команды записи), tooltip «Обязательное поле», сабмит не блокируется.

Маркер `*` в шапке остаётся колоночным (`col.required`): условная
обязательность строки не должна помечать всю колонку.

### Служебный статус ключа

Тот же класс ключей, что `__rowParentIds` (SCRUM-332 §3):

- колонкой не отображается — колонки строятся только из дерева `ViewNode`;
- значением ячейки не пишется — `updateCell` вызывается только с `col.binding`
  реальной колонки;
- в полном снимке строк (`ADR-0011 §3.4`, `fullSnapshot: true`) ключ уезжает
  обратно как есть — ровно так же, как `__rowParentIds`; отдельного вырезания
  служебных ключей из снимка нет, на save бэк их отбрасывает.

## 4. Проверка

«Приём на работу» → вкладка «Начисления» → в строке выбрать источник «Деньги от
реализации…» → ячейка «Код платных услуг» этой строки помечается обязательной;
в соседней строке с «Бюджетными средствами» — нет.

Тесты: `src/features/sdui/lib/utils/is-cell-required.test.ts`,
`src/features/sdui/lib/utils/build-column-defs.test.ts`
(describe «условно обязательная ячейка (`__requiredCells`)»).
