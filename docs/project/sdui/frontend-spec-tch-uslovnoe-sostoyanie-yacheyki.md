# Условное состояние ячейки и строки ТЧ — `__requiredCells` / `__readonlyCells` / `__rowReadonly`

Дата: 15.08.2026. Бэкенд реализован и покрыт тестами.
Основание: репорт «не подсвечивается обязательное поле» + перенос

## 1. Задача

В 1С доступность ячейки ТЧ зависит от значений в той же строке: «Код платных
услуг» обязателен только при источнике финансирования «Деньги от реализации…» и
недоступен при любом другом; «Количество ставок» недоступно при фиксированных
способах расчёта; «Индексируемый»/«Неиндексируемый заработок» гасят друг друга.

Колоночные `props.required`/`props.readonly` это выразить не могут — они про всю
колонку, а условие построчное: соседние строки одной ТЧ в разных состояниях.

## 2. Контракт бэка

Служебные ключи приходят внутри объекта строки, рядом с `rowId`:

```json
{
  "rowId": "12345",
  "IstochnikFinansirovaniya": {
    "id": 501,
    "presentation": "Деньги от реализации…"
  },
  "KodPlatnykhUslug": null,
  "__requiredCells": ["KodPlatnykhUslug"],
  "__readonlyCells": ["NedelnayaNagruzka", "Razmer"],
  "__rowReadonly": true
}
```

| Ключ              | Тип                  | Значение                                  |
| ----------------- | -------------------- | ----------------------------------------- |
| `__requiredCells` | массив кодов колонок | ячейки обязательны в этой строке          |
| `__readonlyCells` | массив кодов колонок | ячейки недоступны для ввода в этой строке |
| `__rowReadonly`   | булев                | недоступна строка целиком                 |

Ключа нет вовсе, если правило не сработало — пустых массивов бэк не шлёт,
поэтому «нет ключа» и «пустой массив» на фронте равнозначны. Снятие состояния —
это строка, приехавшая без ключа; отдельной команды «сбросить» нет.

Каналы доставки: **OPEN** — строки размечены сразу в дереве формы, **EVENT** — те
же ключи в `setValue`-патче на ТЧ. Оба считает один серверный код.

## 3. Реализация на фронте

Правила ячейки — `src/features/sdui/lib/utils/resolve-cell-state.ts`:

```ts
readonly =
  col.readonly ||
  row.__rowReadonly === true ||
  row.__readonlyCells?.includes(col.binding)
required =
  !readonly && (col.required || row.__requiredCells?.includes(col.binding))
```

`readonly` сильнее `required` (§3.3 спеки): помечать обязательной ячейку, в
которую нельзя вводить, бессмысленно. Взаимоисключающих комбинаций бэк не
присылает, но правило даёт тот же результат и на них.

Точки применения — состояние считается на ЯЧЕЙКЕ, а не на колонке:

- `lib/utils/build-column-defs.ts` — плоская `TABLE_COLUMN` и под-колонки
  `COLUMN_GROUP orientation=VERTICAL` (сложная таблица);
- `ui/nodes/composite/editable-table.tsx` — простая таблица.

Стили не новые: `readonly` уходит в ту же readonly-ветку `TableCellEditor`
(текст вместо редактора), `required` — в `RequiredCellFrame` (красная рамка у
пустой ячейки после blur либо сразу при `revealErrors`, tooltip «Обязательное
поле»). Сабмит не блокируется — как в 1С, где процедура клиентская, без `Отказ`.

Маркер `*` в шапке остаётся колоночным (`col.required`): условное состояние
строки не должно помечать колонку целиком.

### OPEN работает без отдельной поддержки

`replaceAll(res.state)` в `lib/dispatch.ts` кладёт строки в стор как есть,
нормализации строк ТЧ между ответом и `useBindingValue` нет — ключи доезжают до
рендера обоими каналами. Поэтому пометки видны сразу на открытии сохранённого
документа, не трогая таблицу (приёмочная проверка №2).

### Служебные ключи не уезжают обратно

`lib/utils/service-row-keys.ts` — `omitServiceRowKeys(row)`, отсев по префиксу
`__`, а не по списку ключей: класс пополняется на бэке по мере переноса правил,
и забытый в списке ключ уехал бы обратно как «значение ячейки». Применяется в
двух местах:

- **исходящий снимок ТЧ** (`use-table-sync.ts`, `sendEvent`) — бэк считает
  состояние сам на каждом OPEN/EVENT, эхо в каждом коммите ячейки было бы лишним
  трафиком. Локальный снимок (`localRows`/`sentRows`) остаётся ПОЛНЫМ: по нему
  рисуется состояние ячеек и работает сравнение «сервер уже знает набранное»;
- **копирование строки** (`editable-table.tsx`, `complex-editable-table.tsx`) —
  «Скопировать» переносит значения; состояние посчитано для источника, и без
  очистки копия заблокированной строки приезжала бы заблокированной ещё до
  ответа сервера.

Колонкой ключи не отображаются — колонки строятся только из дерева `ViewNode`.

## 4. Проверка

Приёмочные сценарии из спеки: «Приём на работу» → «Начисления» (источник
финансирования ↔ «Код платных услуг»), открытие сохранённого документа,
«Отпуск» → «Средний заработок» (индексируемый/неиндексируемый), «Поступление от
контрагента» → «Основные средства» (снятие «Принять к учёту»).

Автотесты: `resolve-cell-state.test.ts` (матрица правил и приоритет),
`service-row-keys.test.ts`, `build-column-defs.test.ts` (describe «условное
состояние ячейки»), `use-table-sync.test.tsx` («служебные ключи строки не уезжают
в EVENT» + «ключи из серверного канона переживают наложение локальных правок» —
пин канала EVENT для сценария «Отпуск»).

## 5. Что осталось на стороне бэка

Новая строка «Начислений» приезжает заблокированной целиком: пустой способ
расчёта не входит в разрешённый набор (§7 спеки — известное поведение, не баг).
Значение заблокированной ячейки не чистится, цветовое оформление 1С
(`ЦветФона`/`ЦветТекста`) не переносится.
