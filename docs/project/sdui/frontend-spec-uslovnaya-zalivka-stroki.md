# Условная заливка строк таблицы — `props.rowAppearance`

Дата: 25.08.2026. Фронт реализован и покрыт тестами, эмиссия на бэке — за
командой webbuh.
Основание: трек «КБП-ТАРИФИКАЦИЯ», сверка 587 (Д-3/П.3 тестировщиков) —
подсветка рассчитанных работников в документе Тарификация.

Связанные документы: `frontend-spec-tch-uslovnoe-sostoyanie-yacheyki.md`
(служебные ключи строки — соседний класс правил), ADR-0011 (TABLE_COLUMN).

## 1. Задача

1С в форме Тарификации выполняет `УстановитьУсловноеОформлениеФормы`: строки
списка «Итоги по работникам» с отбором `РаботникРассчитан = Истина` заливаются
фоном RGB (200, 255, 210). Признак пересчитывается мгновенно — после «Рассчитать
работника» строка зеленеет без переоткрытия документа.

В контракте SDUI цветового оформления строк не было: единственный цветовой ключ
`NodeProps.COLOR` относится к BADGE, а перстрочные служебные ключи
(`__rowReadonly`, `__requiredCells`, `__readonlyCells`, `__rowParentIds`) —
поведенческие.

`ConditionalAppearanceEngine` из reportalt для этого не годится: он работает по
метаданным колонок отчётов с закрытым whitelist'ом правил.

## 2. Контракт

Проп **узла таблицы** (TABLE), а не строки:

```json
{
  "id": "table.itogiPoRabotnikam",
  "type": "TABLE",
  "binding": "ItogiPoRabotnikam",
  "props": {
    "editable": true,
    "rowAppearance": [
      {
        "binding": "RabotnikRasschitan",
        "equals": true,
        "backgroundColor": "rgb(200, 255, 210)"
      }
    ]
  }
}
```

| Поле              | Тип          | Обяз. | Значение                                                        |
| ----------------- | ------------ | ----- | --------------------------------------------------------------- |
| `binding`         | строка       | да    | код колонки, по значению которой идёт отбор; может быть скрытой |
| `equals`          | любое        | нет   | искомое значение; поля нет ⇒ `true` (булев признак «включено»)  |
| `backgroundColor` | строка (CSS) | да    | фон строки: `"rgb(200, 255, 210)"`, `"#c8ffd2"` — как прислали  |

Правила применяются по порядку, побеждает **первое сработавшее** — как порядок
элементов условного оформления в 1С. Ни одно не сработало ⇒ строка обычная.

Правило без `binding` или без `backgroundColor` фронт молча отбрасывает
(раскладка приезжает из БД, опечатка в одном правиле не должна ронять таблицу).

Проп принимается в двух видах: массивом (как его собрал композер) и **строкой
JSON** — сид кладёт значение в `layout_node_props.prop_value` текстом, а
`NodeBuilder.coerceProp` приводит к Java-типу только INTEGER и BOOLEAN, поэтому
`prop_type='JSON'` уезжает на фронт строкой. Разбирать её отдельно на бэке не
нужно.

### Сравнение значений

- Ссылочное/enum-значение `{id, presentation}` сравнивается по `id` —
  представление зависит от языка.
- `"true"` / `"false"` равнозначны булевым: форма записи значения в раскладке и
  патчах не должна менять результат отбора.
- `"equals": null` — отбор «значения нет»: подходит `null`, `""` и отсутствие
  ключа в строке.

### Почему проп узла, а не служебный ключ строки

Служебные ключи описывают ПОВЕДЕНИЕ строки, которое умеет посчитать только
сервер (правила доступности из модулей 1С). Здесь всё условие — «значение
колонки равно X», и признак уже лежит в данных строки. Отсюда два следствия:

- бэку достаточно одной строки в раскладке (SQL-сид пропа), построчной эмиссии
  и трафика на каждый OPEN/EVENT нет;
- заливка пересчитывается на фронте из значения колонки, поэтому строка зеленеет
  сразу после патча этой колонки — приёмочный пункт «без переоткрытия документа»
  выполняется, даже если сервер не переслал никакого оформления.

## 3. Реализация на фронте

- `src/features/sdui/lib/utils/row-appearance.ts` — разбор пропа
  (`parseRowAppearance`) и подбор цвета для строки (`resolveRowBackground`);
- `src/features/sdui/types/view.ts` — тип `RowAppearanceRule`;
- точки применения — все три рендерера строк TABLE:
  `ui/nodes/composite/complex-editable-table.tsx` (сюда попадает «Итоги по
  работникам»: `editable=true` + колонки с `footer`),
  `ui/nodes/composite/editable-table.tsx`, `ui/nodes/composite/read-only-table.tsx`.

Заливка ставится простым `backgroundColor` в `sx` строки. У выделения и ховера
MUI селекторы с классом-модификатором (`.MuiTableRow-root.Mui-selected`), они
специфичнее — выделенная строка остаётся отличимой поверх условного фона.

Тесты: `lib/utils/row-appearance.test.ts` (правила),
`ui/nodes/composite/complex-editable-table.test.tsx` — блок «условная заливка
строк», включая сценарий «строка зеленеет после патча признака».

## 4. Что нужно от бэка для приёмки

Засеять на узле `table.itogiPoRabotnikam` документа Тарификация:

```sql
('table.itogiPoRabotnikam', 'rowAppearance',
 '[{"binding":"RabotnikRasschitan","equals":true,"backgroundColor":"rgb(200, 255, 210)"}]',
 'JSON')
```

Колонка `RabotnikRasschitan` уже заполняется свёрткой
(`TarifikatsiyaItogiComposer`, `COL_RABOTNIK_RASSCHITAN`) и остаётся скрытой —
для отбора видимость колонки не нужна.

Приёмка: строки рассчитанных работников светло-зелёные (200, 255, 210); после
«Рассчитать работника» строка зеленеет без переоткрытия документа.
