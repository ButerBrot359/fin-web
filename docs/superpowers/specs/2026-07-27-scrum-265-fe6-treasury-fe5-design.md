## 1. FE-6 — DATE-поля как `YYYY-MM-DD` (приоритет высший, баг данных)

**Проблема.** `shared/ui/inputs/datetime-input.tsx:44` в `handleChange` делает `newValue.toISOString()` и для `dateOnly`. MUI DatePicker отдаёт `Date` на локальную полночь; `toISOString()` уводит её в UTC → для пользователя восточнее Гринвича «01.07 00:00 (+05:00)» превращается в `"2026-06-30T19:00:00.000Z"`, а сервер (политика «offset отрезаем, не конвертируем») сохраняет **30 июня**. После серверного месяц-гейта в Табеле (волна 4) это стало жёстким блоком: «Заполнить» за полный месяц не работает.

**Решение (чисто клиентское, бэк ничего не меняет).**
- `datetime-input.tsx`, ветка `dateOnly` в `handleChange`: `format(newValue, 'yyyy-MM-dd')` вместо `toISOString()`. `date-fns` уже в зависимостях (в файле уже импортится `parseISO`). `format` работает в локальной зоне — сдвига нет по построению.
- Ветку `datetime` НЕ трогать — политика «UTC на проводе» для полей со временем остаётся (отдельный вопрос вне FE-6).
- Заодно: `pages/financing-plan-upload/financing-plan-upload-list/ui/financing-plan-upload-page.tsx:47` — `todayIso = new Date().toISOString().slice(0,10)` имеет тот же баг (до 05:00 в КЗ вернёт вчера) → `format(new Date(), 'yyyy-MM-dd')`.
- `use-document-entry-form.ts` (`Data: new Date().toISOString()`) — это DATETIME-дата документа, по текущей политике оставляем.

**Отображение** не меняется: `parseISO("2026-07-01")` даёт локальную полночь, существующий рендер значений тот же.

**Тесты (Vitest).** Юнит на инпут: с `TZ=Asia/Almaty` и `TZ=America/New_York` выбор даты в пикере диспатчит ровно `YYYY-MM-DD` выбранного дня; регресс — datetime-режим по-прежнему шлёт ISO Z-строку.

**Верификация (e2e).** Табель: новая форма → Организация + период 01.07–31.07 из пикера → «Заполнить» заполняет таблицу (сейчас — ошибка «период внутри одного месяца»). В devtools payload EVENT: дата уходит как `"2026-07-01"` без `T…Z`. Сохранить документ с DATE-полем → перечитать → дата не сдвинулась.

## 2. Treasury — страница «Выгрузка документов в казначейство» (v6 + v7)

**Бизнес-контекст.** В 1С кнопка «Выгрузить в казначейство» (Заявка на регистрацию ГП сделки / Счёт к оплате) открывает обработку: таблица выгружаемых документов с построчными проверками, поле каталога, чекбокс формата MX, кнопки «Выгрузить»/«Отмена». Раньше webbuh по кнопке сразу качал XML; теперь SDUI-эффект кнопки шлёт `navigate` на `/treasury-export?typeCode=…&id=…`, а проверка/выгрузка — отдельные вызовы со страницы.

### 2.1 Размещение (FSD, легаси-контур)

- `pages/treasury-export` + `features/treasury-export`. Это **НЕ SDUI-экран** — обычная страница легаси-контура, образец `pages/financing-plan-upload` (SCRUM-72). SDUI-эффект `navigate` просто ведёт на роут — границу не смешиваем.
- Роут `/treasury-export` (lazy) в `src/app/App.tsx` (там простой `<Routes>`/`<Route>` с lazy-импортами). SDUI navigate уже роутит через react-router (`features/sdui/lib/effect-handler.ts:28` → `deps.navigate(route)`), фронту в SDUI ничего менять не надо.
- Вход: `?typeCode&id` через `useSearchParams`.

### 2.2 API (бэк уже готов — контракт из v6, без изменений в v7)

- `POST /api/treasury-export/preview` — построчная проверка, 200 даже при ошибках. Ответ `data: { rows[], hasErrors }`, строка: `{ n, documentId, typeCode, presentation, amount, errors[], fileName }`.
- `POST /api/treasury-export/download` — повторная проверка; все валидны → бинарь + `Content-Disposition`; хоть одна ошибка → 422 (`DocumentValidationException`, тело — JSON, при `responseType:'blob'` приходит **Blob**).
- `GET /api/document-entries/{typeCode}/{id}/treasury-export` — одиночный документ, `Content-Disposition: attachment; filename*=UTF-8''…xml` (safe-net, используем для одиночного скачивания).

### 2.3 UI (паритет 1С)

- **Авто-preview при маунте:** дёрнуть `preview` с одним item — таблица заполняется сразу. Отличие от 1С (там колонки пусты до «Выгрузить») — осознанное улучшение UX, **помечаем аналитику** (v7 §3.4).
- **Таблица** (структура готова к многострочности): N / Документ (`presentation`) / Сумма (`amount`) / Ошибки (`errors.join("; ")`, красным при непустых) / Имя файла (`fileName`).
- **Блок «Подробный текст ошибок проверки»** под таблицей — неубираемый, `rows.flatMap(r => r.errors)` (v7 §3.3, улучшает UX).
- **Чекбокс «Включать поля формата MX»** — disabled + tooltip «МХ-формат — в разработке» (паритет расположения; в API не передаётся).
- **Поле «Каталог выгрузки»** НЕ рисуем (сервер не пишет на диск пользователя; в вебе 1С без файлового расширения ведёт себя так же). Вместо него подпись «Файлы будут скачаны браузером».
- **Кнопки** «Выгрузить» (primary) / «Отмена» (назад).
- Тексты — `useTranslation` + новые ключи в `common.json`; текстовые элементы — `<Typography>` (MUI).

### 2.4 Скачивание (исправленный паттерн v7)

- **Одиночный документ (MVP):** сначала валидация (авто-preview уже дал `hasErrors`, либо повторный preview перед скачиванием). Если `hasErrors` — показать ошибки, НЕ качать. Если чисто — **нативная GET-навигация**:
  ```ts
  window.location.assign(
    `${import.meta.env.VITE_API_BASE_URL}/api/document-entries/${typeCode}/${id}/treasury-export`
  )
  ```
  Браузер сам берёт имя из серверного `Content-Disposition` (`filename*=UTF-8''ЗаявкаГПС<Номер>.xml`) — JS в формировании имени не участвует, UUID-бага (blob + `<a download>`) нет по построению. Ответ `attachment` → страница не уходит.
- **Пакет ZIP (фаза 2, откладываем):** у кнопки сейчас только одиночный вход (multi-select в списке — вне объёма). Таблицу делаем многострочной на будущее, но код скачивания в MVP — только GET-навигация одиночного. Когда появится пакет: `POST /download` + blob, парс 422-Blob через `await (error.response.data as Blob).text()` + `JSON.parse`, имя ZIP `Казначейство_<yyyy-MM-dd>.zip` проставить явно; утилиту разбора `Content-Disposition` поднять в `shared/lib`.

### 2.5 Типы

```ts
interface TreasuryExportItem { typeCode: string; id: number }
interface TreasuryExportPreviewRow {
  n: number; documentId: number; typeCode: string;
  presentation: string; amount: number | null;
  errors: string[]; fileName: string | null;
}
interface TreasuryExportPreviewResponse { rows: TreasuryExportPreviewRow[]; hasErrors: boolean }
```

### 2.6 Тесты и верификация

- Vitest: preview рисует строки и построчные ошибки; `hasErrors` блокирует скачивание; чистый результат инициирует GET-навигацию на `/api/document-entries/{typeCode}/{id}/treasury-export`.
- e2e: один валидный документ → «Выгрузить» → файл `ЗаявкаГПС<Номер>.xml` (правильное имя + расширение), страница не уходит; в Network — GET с `Content-Disposition`. Документ с ошибками → блок/тост с читаемым текстом (не `[object Blob]`), скачивания нет.

## 3. FE-5 — адаптивный overflow командной панели формы (приоритет ниже, UX-паритет, не блокер)

**Контекст.** В 1С расположение «Печать»/«Отчеты» (ряд vs «Ещё») — не правило документа, а динамическая компоновка БСП по ширине окна. Backend откатил серверные правила (все кнопки у всех типов); чтобы вести себя как 1С при узких окнах, панели нужен клиентский overflow. Состав/порядок узлов от сервера не меняются — overflow это view-слой.

**Поведение.**
- Контейнер: SDUI-узел `commandBar` (TOOLBAR) формы документа.
- При нехватке ширины кнопки сворачиваются в «Ещё» **справа налево** (первыми — ближние к «Ещё»), при расширении возвращаются в исходном порядке. Порог с гистерезисом (не мигать на границе).
- Никогда не сворачиваются: `btn.postClose` (primary), `btn.more`, `spacer.more`.
- Свёрнутые — отдельной верхней секцией в меню «Ещё» (разделитель перед `mi.more.*`); дропдауны (Печать/Отчеты) — подменю/секции.
- `enabled:false`/`tooltip` свёрнутой кнопки сохраняются (синергия с FE-2).

**Реализация.** Слой `features/sdui`, рендер TOOLBAR: обёртка с `ResizeObserver` на контейнер + замер ширин детей → функция распределения (ширины + доступная ширина → список свёрнутых node id, правило «справа налево», неприкасаемые postClose/more/spacer). Чистый локальный UI-state, без server state (TanStack Query не задействован).

**Тесты.** Vitest: юнит на функцию распределения (какие id свёрнуты при заданных ширинах); рендер-тест — свёрнутая кнопка появляется пунктом в «Ещё» и диспатчит ту же команду.
