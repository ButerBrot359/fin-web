# SDUI-узел `CALENDAR` — рендерер годового календаря графика работы

**Тикет:** SCRUM-278 «Графики работы» (эпик SCRUM-275 «Кадровый учёт»)
**Дата:** 2026-07-29 · **Зона:** SDUI (`src/features/sdui/`), легаси не трогаем
**Источник требований:** `specs-local/scrum-278-grafiki-raboty/231-kalendari-e4b-front-peredacha.md` (передача фронту, бэк готов и на проде)

## Контекст

Карточка справочника «Календари» получает вкладку «Результат заполнения» с узлом нового типа `CALENDAR` — годовой календарь графика работы с ручным переключением дней. Всё остальное (данные, валидации, запись в регистры) — на сервере. Задача **фронт-only**: отрендерить узел и обработать две команды. Отмены нет — сервер пишет регистры сразу на `den.toggle` (платформенное ограничение).

## Контракт узла (сервер уже отдаёт)

```json
{ "id": "kalendari.rezultatZapolneniya",
  "type": "CALENDAR",
  "props": {
    "god": 2025,
    "godMin": 2021,
    "godMax": null,
    "redaktiruemyy": true,
    "dni": [ { "data": "2025-01-01", "vklyuchen": false, "ruchnoy": false },
             { "data": "2025-01-02", "vklyuchen": true,  "ruchnoy": false },
             { "data": "2025-03-15", "vklyuchen": false, "ruchnoy": true } ]
  } }
```

- `dni` — ВСЕ дни года `god` по возрастанию (365/366 элементов), пропусков нет.
- `godMin`/`godMax` — границы селектора года; `godMax: null` = верхней границы нет.
- `redaktiruemyy: false` — карточка ещё не записана: календарь показывается, клики НЕ отправляем.

## Решения по UX (согласовано в брейншторме)

- **Раскладка:** фиксированная сетка **4×3** (4 колонки × 3 ряда месяцев). На узкой области — горизонтальный скролл внутри блока (`overflow-x:auto`), страница по горизонтали не скроллится.
- **Легенда, три состояния:** **Рабочий** (`vklyuchen=true`, акцентный цвет текста) · **Нерабочий** (`vklyuchen=false`, приглушённый) · **Изменён вручную** (`ruchnoy=true`, выделенный ФОН ячейки поверх любого цвета текста).
- **Неделя** начинается с понедельника.
- **Селектор года:** стрелки ◀ ▶ + дропдаун в диапазоне `godMin..godMax` (`godMax:null` — без верхней границы; для дропдауна берём разумный кап `god + 5`, стрелка «вперёд» при `null` не ограничивается).

## Подход к рендеру

**Кастомная сетка на date-fns** (v4, уже в проекте). Чистый хелпер раскладывает дни месяца по неделям (пн-первый), ячейки свои — полный контроль над тремя состояниями. Отклонён библиотечный путь (MUI `DateCalendar` / react-day-picker): это пикеры дат, ×12 инстансов на год под кастомную toggle-сетку — тяжело и хрупко.

## Архитектура и декомпозиция

Узел `CALENDAR` регистрируется в `component-registry.ts`; тип добавляется в union `NodeType` (`types/node-types.ts`). Патч `replaceNode` уже поддержан (`patch-applier.ts` `case 'replaceNode'`) — узел перерисовывается сам через существующий пайплайн `dispatch → applyTreePatches`, спец-обработки патча в ноде не нужно.

Файлы (цель ~200 строк/файл, баррелей внутри сегмента не создаём):


## Поток данных, команды и патчи

Нода рендерит из `node.props` — своего состояния данных не держит.

**Клик по дню** (только `redaktiruemyy=true`):
```
CalendarDayCell.onClick
  → dispatch({ type:'COMMAND', command:'kalendari.den.toggle', value:'2025-03-15', sourceNodeId:node.id })
  → сервер: patches:[{ op:'replaceNode', nodeId:'kalendari.rezultatZapolneniya', node:{…} }]
  → applyTreePatches → tree-store заменяет узел → перерисовка
```

**Смена года** — аналогично: `command:'kalendari.god.change', value:2026` → тот же `replaceNode`.

Диспатч через `useSduiDispatch()`, как штатные `dict.save*`. `behavior` не требуется (передаём `null`/не передаём).

**Инстанс `CalendarNode` переживает `replaceNode`**: узел сохраняет `id`/тип/позицию в дереве, родитель рендерит детей по `key=id` → React сохраняет фибру, меняются только props. Значит локальный `useState` ноды живёт в пределах сессии вкладки.

## Одноразовое уведомление

«Изменения применяются сразу» — локальный `useState(false)` в `CalendarNode`. На первом успешном `den.toggle` в сессии: `showToast('info', t('sdui.calendar.applyImmediately'))` (`@/shared/ui/toast/show-toast`) и флаг → `true`. Живёт до перемонтирования вкладки = «в сессии», как требует спека.

## Edge-cases и ошибки

- `redaktiruemyy=false` — дни некликабельны, `cursor:default`, клик не диспатчится (guard в ячейке). Визуально обычные.
- **Ошибка сервера** (год вне границ / незаписанная карточка / битая дата) приходит `effects:[{type:'notify', level:'error', message}]` — уже играется `effect-handler` (toast), узел не меняется. Своего кода не пишем.
- **Пустой год** (в приёмке 2021–2024) — все дни `vklyuchen=false` → приглушённые, без ошибок.
- Смена года при «несохранённых изменениях» подтверждений не требует — их не бывает, всё уже записано.

1. График «01» (Пятидневка-36) → «Результат заполнения»: 2025, **246 дней** акцентным цветом, остальные приглушённые.
2. Клик по рабочему дню → гаснет СРАЗУ + фон «ручной»; повторный клик — обратно (фон «ручной» остаётся).
3. Селектор: 2026/2027 — данные; 2021–2024 — пустой год (все приглушённые), без ошибок.
4. График «03» (Семидневка): ВСЕ дни года акцентные, включая 1 января.
5. Новая (незаписанная) карточка: календарь виден, клики не уходят.

## Открытый пункт координации с бэком (не блокер старта)

Сверить регистр op патча: фронт применяет **`replaceNode`** (camelCase — `patch-applier.ts`, `validation.ts` `z.literal('replaceNode')`), а передаточная спека написала `REPLACE_NODE`. Весь SDUI-контракт на camelCase, так что спека почти наверняка неформальна, но если сервер реально шлёт верхний регистр — патч уходит в `default` (warn) и календарь не обновится. Проверяется тестом сериализации бэка (`KalendariRezultatComposer` / `KalendariKalendarCommandService`) или первым живым ответом. Заодно подтвердить форму команд `{type:'COMMAND', command, value}`.

## Границы (YAGNI)

- Дублировать серверные правила (какой день рабочий, границы года) на клиенте не нужно — источник истины сервер.
- Никакой оптимистичной перерисовки/отмены — ждём `replaceNode` от сервера.
- Никаких сущностно-специфичных знаний о «Календарях» в коде: поведение приходит с сервера, узел универсален.
