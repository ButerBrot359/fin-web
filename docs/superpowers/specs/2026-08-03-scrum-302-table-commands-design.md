# SCRUM-302: доменные кнопки командной панели табличных частей — дизайн

Дата: 2026-08-03. Статус: аппрувнут.
Источник требований: спека бэка `specs-local/scrum-302-masshtabirovanie-knopok-2/SCRUM-302-spec-v1-2026-07-28-back.md` (вложение тикета).

## 1. Задача

Бэкенд присылает в `props.tableCommands` TABLE-узла дескрипторы доменных кнопок
(«Подбор», «Рассчитать оклад», «Заполнить табельные номера»). Фронт этот prop не
читает — кнопок на экране нет. Дополнительно доводим командную панель ТЧ до
паритета с 1С: меню «Ещё», перенос «Удалить» внутрь него, клиентский поиск,
хоткеи.

Работа в два этапа внутри одной таски:

- **Фаза 1 — ядро:** рендер `tableCommands`, диспатч команд, спека-v2 бэку.
- **Фаза 2 — паритет:** новый layout панели, «Ещё», поиск, хоткеи, «Скопировать».

Зона — только SDUI (`src/features/sdui`). Легаси не трогаем.

## 2. Контракт

### 2.1 Дескриптор

В `features/sdui/types/view.ts`:

```ts
export interface TableCommandDescriptor {
  command: string // непрозрачная строка, не разбирать
  label: string
  labelKz?: string | null
  enabled: boolean
  disabledReason?: string | null
  behavior: ActionBehavior
  column?: string | null // служебное поле бэка, фронт не использует
  inMoreMenu?: boolean // true ⇒ продублировать пункт в «Ещё»
}
```

Читается из `node.props.tableCommands` в `editable-table.tsx` и
`complex-editable-table.tsx`, прокидывается в `TableToolbar`. В сторы не
дублируется — дескрипторы живут жизнью дерева. `tableCommands` отсутствует или
пуст ⇒ доменных кнопок нет, всё остальное работает.

`behavior` берётся только из дескриптора (§6.6 спеки бэка): никаких списков
мутирующих команд и парсинга префиксов на фронте.

Подпись: `labelKz ?? label` при казахском языке интерфейса, иначе `label`.

### 2.2 Расхождение со спекой бэка — закрывается спекой-v2 (фронт → бэк)

Спека бэка от 28.07 писалась против фронта до мержа SCRUM-284 Δ4 (тот же день).
Её §6.2–6.3 (править `needsSelectedRow`, `refCommandField`) неактуальны: этих
механизмов больше нет, фронт читает `requiresSelectedRow` / `selectionField` с
click-action узла и селекшен-ключ не выводит из имени команды. Фронтовых правок
под §6.2–6.3 не требуется. Вместо них — три пункта в спеку-v2-front:

1. **Δ4-поля на action, не в props.** В панели подбора кнопка «Выбрать» и LIST
   должны получать `requiresSelectedRow: true` и
   `selectionField: "table.<tableCode>"` на своих action'ах (`click` /
   select-action). `props.selectionKey` / `props.requiresSelectedRow` фронт не
   читает.
2. **Формат value.** Кнопка с `requiresSelectedRow` шлёт
   `value: { id: <rowId> }` (единый формат всех пикеров после Δ4), а не голое
   число, как в примере §3 шаг 2. Бэку принимать объект.
3. **`labelKz` избыточен** — язык фиксируется на OPEN, при смене языка форма
   переоткрывается; бэк может локализовать `label` сервером, как остальные
   подписи. Не блокер: фронт поддерживает `labelKz` фолбэком в одну строку.

### 2.3 Сценарий «Подбор»

Ничего нового не рендерим: `openDialog` приходит со стандартной панелью
`CHOICE_FORM`, которая уже работает для ссылочных полей. Панель не закрываем
после выбора — только `closeDialog` от сервера или действие пользователя
(текущее поведение диалогов, `closeAfter: false`).

Пустой ответ (`patches: [], effects: []`) — штатный отказ дубля: no-op, без
тоста и изменения состояния.

## 3. Фаза 1 — ядро

`TableToolbar` получает `commands?: TableCommandDescriptor[]` и рендерит
доменные кнопки после встроенных, в порядке массива:

- `disabled={!enabled}`, tooltip из `disabledReason` (span-обёртка вокруг
  disabled-кнопки, как в `button-node.tsx`);
- клик → `dispatch({ type: 'COMMAND', command }, behavior)` через существующий
  `useSduiDispatch` — `flushPendingTables` он уже отрабатывает.

Обработчик один: его же используют пункты «Ещё» в Фазе 2.

## 4. Фаза 2 — паритет панели с 1С

### 4.1 Layout

```
было:   [Добавить] [Удалить] [↑] [↓]
стало:  [Добавить] [↑] [↓] [доменные…]  ←распорка→  [Поиск ✕] [Ещё ▾]
```

«Удалить» уходит из ряда совсем; `allowDelete` гейтит только пункт в «Ещё».
«Ещё» показывается на каждой ТЧ, даже без доменных команд.

### 4.2 Новые файлы (все в `features/sdui`)

| Файл | Ответственность |
|---|---|
| `ui/nodes/composite/table-more-menu.tsx` | MUI `Menu`/`MenuItem`: стандартный блок, разделитель, доменные пункты (`inMoreMenu: true`). Хоткеи — серым справа |
| `lib/hooks/use-table-search.ts` | Состояние поиска: `query`, совпадения `(rowIndex, columnId)`, текущее, `next()` |
| `lib/hooks/use-table-hotkeys.ts` | `onKeyDown`-обработчик контейнера таблицы |

`TableToolbar` — единственная точка сборки (ряд + поиск + «Ещё»), вызывающие
таблицы прокидывают дескрипторы и колбэки.

### 4.3 Состав «Ещё»

| Пункт | Хоткей | Активен когда |
|---|---|---|
| Добавить | Ins | `allowAdd` |
| Скопировать | F9 | `allowAdd` и выбрана строка |
| Удалить | Del | `allowDelete` и выбрана строка |
| Найти | Ctrl+Alt+F | всегда |
| Отменить поиск | Ctrl+Q | поиск задан |
| Переместить вверх | Ctrl+Shift+↑ | `allowReorder` и не первая |
| Переместить вниз | Ctrl+Shift+↓ | `allowReorder` и не последняя |
| ─── разделитель ─── | | |
| доменные команды | | `enabled` дескриптора |

Осознанные расхождения с эталоном:

- «Изменить» (F2) и «Закончить редактирование» (Shift+F2) не показываем — у нас
  ячейки всегда редактируемые, режима правки нет;
- «Расширенный поиск», «Сортировать ↑/↓», «Вывести список…» — не реализуем
  (§6.4.2 спеки бэка это разрешает);
- «Найти» фокусирует поле поиска без подстановки значения текущей ячейки —
  понятия «текущая ячейка» в нашей модели нет, выбор построчный.

### 4.4 «Скопировать»

Без правок `use-table-sync`: существующий `addRow(columns, presetValues)`
вызывается со значениями выбранной строки минус `rowId`. Ссылочные ячейки
(`{ id, presentation }`) копируются как есть.

### 4.5 Поиск (Ctrl+F)

Клиентский, по загруженным строкам, **не фильтрует** (§6.5: это перемещение
курсора, не отбор). Матчинг по строковому представлению ячейки; для ссылочных —
по `presentation`. Enter циклит совпадения; найденная ячейка подсвечивается
(проп в рендер ячейки) и скроллится в видимость. Крестик/Esc — сброс.

### 4.6 Хоткеи

Слушаем на контейнере таблицы, не на `document` — на форме несколько ТЧ,
работает та, где фокус:

- Ins → добавить, F9 → скопировать, Del → удалить,
  Ctrl+Shift+↑/↓ → переместить, Ctrl+Q → сброс поиска,
  Ctrl+F и Ctrl+Alt+F → фокус в поле поиска (`preventDefault` только внутри ТЧ);
- фокус в инпуте ячейки ⇒ Ins/F9/Del игнорируются (пользователь печатает),
  Ctrl-комбинации работают.

## 5. Ошибки и краевые случаи

- `enabled: false` → серая кнопка/пункт с tooltip `disabledReason`.
- Пустой ответ на дубль — no-op (без тоста).
- `rowId` серверных строк нечисловой (`tmp-srv-…`) — не приводить к числу;
  `getRowId` уже строковый.
- `notify: warning` от «Рассчитать оклад» / «Заполнить табельные номера» —
  существующий механизм эффектов, нового UI нет.

## 6. Тесты

Vitest + RTL, рядом с компонентами (образец — `button-node-*.test.tsx`):

- тулбар: порядок доменных кнопок, disabled+tooltip, `dispatch` с командой и
  `behavior` из дескриптора, «Удалить» в ряду отсутствует;
- «Ещё»: состав, активность, доменная секция после разделителя, общий
  обработчик с кнопками ряда;
- поиск: матч по `presentation`, Enter циклит, строки не фильтруются;
- хоткеи: Del в инпуте ячейки игнорируется, Ctrl+Shift+↑ на первой строке no-op;
- «Скопировать»: `addRow` с пресетами без `rowId`.
