# SCRUM-291 «Перевод экранов на SDUI» — roadmap фронт-дельты

Дата: 2026-08-05. Тип документа: **декомпозиция/порядок** (не имплементационная спека).
Источник истины по контрактам: `specs-local/scrum-291-perevod-ekranov-na-sdui/frontend-spec-list-form.md`
(вложение Jira SCRUM-291, версия от 2026-08-03) + связанные ADR (0034/0035/0025/0026/0028).

## Зачем этот документ

SCRUM-291 — не одна фича, а большой пакет фронт-дельты поверх уже сданного/спроектированного
бэкенда. Спека из Jira — подробная имплементационная инструкция вплоть до тестов, но она склеивает
три контура (LIST_FORM, CHOICE_FORM, REPORT_FORM) и несколько фаз в один документ. Здесь — карта
кусков, их зависимости и порядок раскатки. Каждый кусок дальше идёт своим циклом
spec-slice → план → имплементация.

Предпосылки на 2026-08-05 (перепроверено grep'ом по `src/`):

- **SCRUM-290 (единый роутинг)** влит в dev/main → хостинг для SDUI-экранов (catch-all + 422-fallback) есть.
- **A3 (`requiresSelectedRow`/`selectionField`)** уже в коде (SCRUM-284/285): `button-node.tsx`,
  `list-node.tsx:122`, тесты `button-node-requires-row.test.tsx`. → пункты «реализовать A3» в
  чек-листах F и J спеки **уже закрыты**; 2e и кнопки CHOICE_FORM гейтятся только бэкенд-флагом.
- Из самого пакета 291 на фронте **не сделано ничего**: нет `isError`/`loadedCount` без total,
  нет `cellKind`/`iconMap`, `allowOpen`/`allowCopy` не читаются, нет `REPORT_RESULT`,
  префикс `tmp-` в `use-table-sync.ts` захардкожен и цикл реконсиляции его не проверяет (дефект 1 жив).

## 2. Граф зависимостей

- **SCRUM-290** ✅ → хостинг для B, H, K уже есть.
- **A3** ✅ (в коде) → F и кнопки J разблокированы со стороны примитива выделения.
- **A1, A2, L** — полностью независимы: бэк не нужен, флагов нет, катятся в любой момент.
- **J** — независим от миграции, но **блокирует снятие флага** `sdui.ref-picker.dictionary-card`
  (CHOICE_FORM Phase 1). Плюс это живой дефект сегодня («+» на классификаторе с запретом «Создать»).
- **2a → 2b / 2c / 2d** — 2a обязателен первым: POST-транспорт + видимая ошибка загрузки. Иначе флип
  `transport:SEARCH` на бэке = молчаливый 400 (легаси-`GET …/search` без `q`), который UI показывает
  как пустой список «документы пропали». Обратный порядок безопасен (бэк на `PAGED` — `method` не шлёт).
- **3b** — нужен фронт-примитив `cellKind`/`iconMap` (переиспользуется под будущую иконку статуса документа).
- **K (REPORT_FORM)** — самостоятелен, зависит только от 290. `props.multiple` = 4-я блокирующая
  зависимость: гейт `multi-ref-enabled` отклоняет отчёт целиком при наличии любого спискового
  параметра (`ACCOUNT_LIST`/`REF_LIST`) — 39 из 63 отчётов, пока `props.multiple` не на фронте.

## 3. Порядок раскатки (утверждён)

1. **A1 (дефект 1)** — первым: единственная порча данных в БД, остальное восстановимо/косметика.
2. **2a (транспорт)** — фундамент миграции списков; разблокирует бэку флип `SEARCH`; headline-KPI таски.
3. **2b → 2c → 2d** — надстройка над 2a, каждый катится независимо.
4. **A2 + J + L** — догоняющий пакет дефектов/мелочей (J разблокирует флаг CHOICE_FORM Phase 1).
5. **3b (cellKind)** — иерархия справочников.
6. **K (REPORT_FORM)** — самый крупный, отдельный цикл дизайн→план.

Каждый пункт — свой цикл spec-slice → план → имплементация. **F/2e, G/3a, I/3d фронт-работы не
требуют** — только визуальная проверка парности колонок/поведения при флипе соответствующего флага.

## 4. Что НЕ входит в пакет (сводка из §10 спеки)

- Список: свободный поиск по документам, `logic=OR`/дерево условий, многополевая сортировка, пресеты
  периода, per-user персист (структурно недоступен — нет реальной идентификации юзера), настройка
  состава колонок, план счетов/регистры (другой контур).
- CHOICE_FORM: пикер в ячейках ТЧ документа/справочника (Phase 2, **не разрешена PM** — блок по
  контракту идентичности строки), составные поля/субконто, standalone-маршрут формы выбора, полное
  удаление легаси `dict-sidebar` (жив, пока есть хоть один `new_view=false`-тип).
- REPORT_FORM: 2 отчёта из 63 (см. §19.4 спеки); фронт **не собирает тело `/run` руками** (§19.6 —
  два расхождения контуров `reports`/`reportalt`).

## 5. Открытые вопросы к бэку (из §12 спеки — не блокируют старт)

- Доп. props колонок (ширина/выравнивание) — сейчас нет; автоширина справочников частично.
- Казахские подписи `filterOpLabels` — черновой перевод, нужна вычитка носителем до массовой раскатки.
- Экспорт: предупреждение об обрезке — баннером в XLSX, не `notify`-тостом (нужен ли toast — отдельно).
- «Стабильный per-session ключ строки ТЧ» — целевое решение для пикера в ячейках ТЧ, отдельная
  задача уровня ADR (ADR-0011), вне этого пакета.
