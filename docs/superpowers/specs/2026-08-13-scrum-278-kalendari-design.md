# SCRUM-278: «Графики работы» (Kalendari) — фронт по спеке бэка v1

**Дата:** 2026-08-13
**Источник требований:** `SCRUM-278-spec-v1-2026-08-12-back.md` (вложение Jira от Talgat Bizhigit, слепок в `specs-local/scrum-278-grafiki-raboty/`). Она отменяет интерактивные пункты `231-kalendari-e4b-front-peredacha.md`: календарь результата теперь строго read-only.
**Канон:** курс «фронт не знает протокол» (`docs/superpowers/specs/2026-07-02-sdui-course-audit.md`, чекпоинт `docs/project/2026-08-12-sdui-checkpoint.md`) — новые протокольные знания регистрируются в реестре отклонений §9.

## Объём работ (спека бэка, §Required frontend work)

1. Enum проносит `{id, code, presentation}` через гидрацию и исходящее состояние.
2. Рендерер таблицы шаблона заполнения (`ShablonZapolneniya`): недельный/циклический режимы, форм-only длина цикла, полномассивная замена.
3. Раскрываемый редактор расписания (`RaspisanieRaboty`) на существующей табличной синхронизации.
4. `CALENDAR` без интерактивных дней при `redaktiruemyy:false`; остаётся только выбор года.

Вне объёма (спека, §Verification and out of scope): назначение сотрудников, расчёт зарплаты, ручное редактирование дней результата, новые API/миграции, персист длины цикла.

## Архитектура

Два новых feature-local компонента в `src/features/sdui/ui/nodes/composite/`:

- `kalendari-template-table.tsx` — шаблон заполнения;
- `kalendari-schedule-table.tsx` — расписание работы.

`table-node.tsx` получает третью ветку роутинга на эти компоненты. Оба строятся поверх существующего `use-table-sync` (`src/features/sdui/lib/hooks/use-table-sync.ts`): он уже шлёт полный локальный снимок строк (ADR-0011 §3.4) — ровно требование спеки «on every table edit send the whole ordered array» — и генерирует `tmp-*` rowId для новых строк. Новых механизмов синхронизации и нового TanStack Query кэша для stateful `/api/view` сессий не создаётся (прямой запрет спеки).

### Дискриминатор роутинга — РЕШЕНО (v2-back 2026-08-13)

Бэк ответил (`SCRUM-278-spec-v2-2026-08-13-back.md`, §1): фронт распознаёт kalendari-таблицы **по `binding`** — `ShablonZapolneniya` (шаблон) и `RaspisanieRaboty` (расписание). Специального пропа (`kalendariKind`/`tableKind`) намеренно НЕТ: классификация ограничена карточкой `Kalendari`. Решение локализовано в одной функции-дискриминаторе в `table-node.tsx`. Это ровно тот фолбэк, что был заложен изначально, — архитектура не меняется.

Прочие пункты v2-back, подтверждающие дизайн: шаблон несёт единственную персистируемую колонку `DenVklyuchenVGrafik` (BOOLEAN/`CHECKBOX_FIELD`); расписание — `NomerDnya` (INTEGER/`NUMBER_FIELD`), `VremyaNachala`/`VremyaOkonchaniya` (DATETIME/`DATETIME_FIELD`); режим читается из enum-поля `SposobZapolneniya` (session-state, `code`); `DlinaTsikla` — фронтовое состояние из `ShablonZapolneniya.length`, ни в EVENT, ни в save не попадает; новые строки — нечисловой `rowId` (`tmp-*`), на любой правке — весь упорядоченный массив TABLE-level EVENT'ом на id ноды.

## Шаблон заполнения (`kalendari-template-table`)

- Строки позиционные: позиция = 1C `LineNumber` = бизнес-ключ. Персистится только `DenVklyuchenVGrafik` (чекбокс). Отдельный номер/код дня не хранится и не отправляется.
- Режим определяется значением enum «Способ заполнения»: `PoNedelyam` — ровно 7 строк, подписи Пн…Вс по позиции (date-fns, как в calendar-node); `PoTsiklamProizvolnoyDliny` — подписи «День 1…N».
- «Длина цикла» — чисто фронтовая ячейка в циклическом режиме: положительное целое 1–366, без binding, никогда не попадает в состояние/EAV/save. Значение выводится из текущего числа строк.
- Смена длины на N: полная замена локального массива — общие позиции сохраняют значения, хвост отбрасывается при уменьшении, новые строки создаются unchecked с `tmp-*` id; отправка целиком через sync.
- Смена режима недели↔циклы — тем же полномассивным путём (7 строк ↔ N строк).
- Дефолты новой карточки (enum `PoNedelyam` + 7 строк `tmp-1…tmp-7`, все unchecked) приходят с бэка; фронт их не генерирует, скелет не теряется и при scalar-only сохранении (бэк мержит сам).

## Расписание работы (`kalendari-schedule-table`)

- Изначально свёрнуто. Раскрывается по кнопке «Заполнить расписание» или клику по саммари уже заполненного времени.
- Внутри — редактируемая таблица интервалов `{rowId, NomerDnya, VremyaNachala, VremyaOkonchaniya}` через тот же `use-table-sync`. Несколько интервалов на один день валидны; в саммари их часы суммируются.
- `NomerDnya: 0` (предпраздничный день) допустим только при `UchityvatPrazdniki=true`; фронт такие строки сам не удаляет — бэк вычищает их при сохранении, если праздники выключены.

## Enum (`enum-field-node`)

- Гидрация: значение binding может прийти строкой-кодом (как сейчас) или полным объектом `{id, code, presentation}`; селект работает по `code` в обоих случаях.
- Исходящее состояние: при выборе в session-state кладётся полный объект (сейчас кладётся голая строка — это и есть потеря формы, п.1 спеки). Change-событие уже шлёт полный объект — не меняется.
- Общий `useFieldNode` не трогается.

## Календарь результата (`calendar-node`)

- Путь `kalendari.den.toggle` удаляется целиком вместе с одноразовым тостом «Изменения применяются сразу» — спека запрещает слать toggle, бэк его отвергает без мутации.
- Остаётся только `kalendari.god.change` в пределах `godMin..godMax`; ответный `REPLACE_NODE` для `kalendari.rezultatZapolneniya` применяется обычным SDUI-редьюсером (уже так).
- Дни всегда disabled/некликабельны. Даты и ручные маркеры вне точного периода графика — неактивны (проверить month-grid/day-cell, поправить при необходимости).
- Начальный `god` приходит с бэка (год `DataNachala`, не браузерный) — фронт не вычисляет.

## Ошибки

Стандартные success/error-нотификации существующего dispatch-пути. При ошибке сохранения клиентское состояние сохраняется (инвариант flush-before-save в `use-table-sync` уже это даёт). Сырой SQL/500-текст не рендерится — только нормализованный текст ошибки. Валидации (дата конца ≥ начала, опорная дата цикла, минимум один рабочий день) — бэковые, фронт не дублирует.

## Тесты

Юнит-тесты (vitest + RTL), рядом с компонентами:

- template-table: подписи по режимам; замена массива при смене длины (сохранение общих позиций, отбрасывание хвоста, unchecked `tmp-*` новые); смена режима; длина цикла не попадает в отправляемые строки.
- schedule-table: свёрнуто по умолчанию, раскрытие по кнопке и по саммари; несколько интервалов на день и сумма часов; day-zero отображается при `UchityvatPrazdniki=true`.
- enum-field: гидрация объекта и строки; полный объект в session-state после выбора.
- calendar-node: клик по дню не порождает никаких dispatch; смена года шлёт только `kalendari.god.change`; маркеры вне периода неактивны.
- table-node: роутинг по дискриминатору на оба новых компонента.

E2e с живым бэком доступен сразу: v2-back (§«No new backend code required. These nodes are emitted by the merged `main` implementation») подтверждает, что бэк уже влит в main и ноды kalendari-таблиц приходят обычной stateful `/api/view`-сессией. Приёмка по чеклисту спеки v1 (7 пунктов) на dev-api.
