# SCRUM-301: даблклик в «Связанных документах» → вкладка документа

**Дата:** 2026-08-13
**Источник требований:** `SCRUM-301-spec-v2-2026-08-12-front.md` (вложение Jira от Talgat Bizhigit, слепок в `specs-local/scrum-301-svyazannye-dokumenty/` — принята как есть, контракт с бэком не меняется).

## Проблема

Даблклик по строке дерева «Связанные документы» зовёт `navigate(route)`, но активной вкладкой workspace остаётся `sdui-panel`. Пока вкладка панели активна, layout скрывает route-children и рендерит хост панели: URL меняется, а карточка документа не показывается.

## Решение

Это требование активации вкладки, а не роутинга. В `handleDoubleClick` (`src/features/sdui/ui/nodes/composite/subordination-tree.tsx`) после резолва маршрута и непосредственно перед `navigate(route)` вызвать `armNewTab()` из gateway `src/features/sdui/lib/workspace-tab-gateway.ts`. App-уровневый биндинг gateway уже маппит `armNewTab()` на workspace-стор: следующий переход создаст/активирует обычную вкладку документа.

Прямой импорт `useWorkspaceTabsStore` в SDUI запрещён — граница только через gateway (существующий, новый не создаётся).

## Поведение (без изменений против спеки v2)

| Взаимодействие                                         | Результат                                                                              |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| Одиночный клик                                         | Только выделение строки (используется тулбаром)                                        |
| «Вывести для текущего»                                 | Перестроение панели от выбранной строки — как раньше                                   |
| Даблклик по строке документа                           | Открыть/активировать вкладку документа с его карточкой; панель остаётся своей вкладкой |
| Даблклик по маркеру усечения (`_isTruncated === true`) | Ничего                                                                                 |
| Строка без `_route`, но с `_type.entityRef`            | Fallback `/documents/<typeCode>/<id>` + то же поведение вкладки                        |
| Строка без обоих источников маршрута                   | Ничего                                                                                 |

## Ошибки

`armNewTab()` при незабинженном gateway возвращает `false` с console.warn и переход происходит в текущей вкладке — прежнее поведение, деградация мягкая. Дополнительной обработки не требуется.

## Тесты

Расширить `src/features/sdui/ui/nodes/composite/subordination-tree.test.tsx`: мок `armNewTab` через gateway-модуль; assert — даблклик по навигабельной строке зовёт `armNewTab()` ровно один раз и `navigate` с `_route`. Существующие тесты (fallback-маршрут, truncation) сохранить.

## Приёмка

По чеклисту спеки v2: на локальном стенде открыть `LT00-00003` → «Связанные документы» → даблклик `LT00-00002` → активна карточка `LT00-00002`, вкладка панели жива и выбирается; «Вывести для текущего» по-прежнему перестраивает панель. Юнит-тесты дерева зелёные; перед пушем `npm run build`.
