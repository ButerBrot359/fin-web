# Конструктор дизайна SDUI: контракт layout-пропов (v1)

Дата: 2026-09-04. Статус: черновик для согласования с бэком.
Контекст: спека `2026-09-03-design-system-audit-design.md` §4.2 («Изменить
форму») — компоновка принадлежит бэку, фронт рендерит дизайн-системно и
ничего не хардкодит под конкретные экраны. Этот документ фиксирует словарь
пропов, которыми бэк (а в фазе 2 — конструктор форм в UI) управляет
раскладкой.

## 0. Принципы

1. **Единицы.** Все размеры-отступы — шаги 4px-шкалы дизайн-системы
   (`gap: 4` = 16px), НЕ пиксели. Ширины панелей/колонок — px (исторический
   контракт таблиц).
2. **Деградация.** Неизвестный проп фронт игнорирует; кривое значение
   клампится к шкале, рендер не падает. Старый бэк ничего не ломает.
3. **Дизайн-константы — фронта.** Цвета, радиусы, тени, шрифты приходят из
   токенов (`tokens.ts` → CSS-переменные, фаза 2 — `/api/theme`). Бэк ими
   не управляет и не шлёт hex.
4. **Пер-пользовательские override'ы** («Ещё → Изменить форму», фаза 2) —
   это те же пропы этого словаря, которые бэк патчит в дерево перед отдачей
   `/api/view`. Конструктору UI ничего фронтового не нужно, кроме диалога,
   шлющего override'ы на бэк.

## 1. Реализовано фронтом (можно слать уже сейчас)

| Проп                       | Ноды                                 | Семантика                                                                                                                             | Фронт-нормализация                                    |
| -------------------------- | ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| `gap: number`              | VSTACK, HSTACK, GRID, GROUP          | Зазор между детьми, шаг ×4px                                                                                                          | нет пропа → 16px; `0` → встык; иначе clamp(×4, 4, 24) |
| `padding: number`          | стек-ноды                            | ИГНОРИРУЕТСЯ (v1): боковые отступы контента задаёт страница/панель                                                                    | вернём в v2 после выравнивания конфигов               |
| `size: 'small'`            | TEXT_FIELD, NUMBER_FIELD, DATE_FIELD | Компактный инлайн-инпут 36px без floating label (поле в строке текста)                                                                | по умолчанию — полноразмерный 50px                    |
| `width: number`            | панель (drawer)                      | Ширина панели, px                                                                                                                     | уважается как есть; канон Figma — 766                 |
| `flex`, `align`, `justify` | стек-ноды                            | Стандартные флекс-пропы                                                                                                               | как раньше                                            |
| `visible`, `enabled`       | все                                  | Видимость/активность                                                                                                                  | `enabled` строго `=== true`                           |
| `pinBottom: true`          | прямой ребёнок VSTACK                | Блок прижат к низу стека растущим зазором (Комментарий/Ответственный у нижней кромки). Требует растянутого родителя (`flex` на стеке) | без пропа — обычный поток                             |
| `dividers: true`           | HSTACK                               | Вертикальная линия `ui-03` между колонками (визуальное разделение соседних таблиц), отступ от линии = gap                             | линий нет                                             |

## 2. Что нужно поменять в конфигах бэка (найдено аудитом Ф3/Ф4)

1. Шкала: конфиги панелей организации/физлица и «Графиков работы» шлют
   `gap`/`padding` в пикселях (`gap: 16` → фронт читает как 64px). Привести
   к шагу ×4; фронт пока клампит, но кламп — страховка, не契 контракт.
2. `width: 900` у SDUI-панелей → 766 (Figma).
3. SEARCH-нода списков — внутрь TOOLBAR-ноды (поиск в одну строку с
   кнопками, Figma ПКО-список 167:5013); убрать вторую пустую TOOLBAR-ноду
   на Kalendari.
4. Кнопка экспорта списка в Excel — эмитить нодой (подвал списка, слева).
5. `size: 'small'` — для инлайн-полей в строках («дней», «начиная с»).
6. `pinBottom: true` — «Комментарий»/«Ответственный» на формах документов.
7. `dividers: true` — HSTACK с двумя ТЧ-таблицами (Регистрация заявлений
   по вычетам ИПН и аналоги).

## 3. v2 (кандидаты, обсуждать по мере надобности)

- `padding` вернуть: шаг ×4, кламп [0..24], запрет на прямом ребёнке PAGE
  (боковые отступы — у страницы).
- `size` для REFERENCE/ENUM/CHECKBOX-полей.
- `widthUnits` для отдельных полей в строке (сейчас ширины полей делит
  HSTACK поровну через flex).
- Пресеты секций (`variant: 'card' | 'plain'` на GROUP).
- `/api/theme` (спека §4.1) — серверные значения токенов; admin-UI темы.
- «Изменить форму»: диалог override'ов (скрыть поле, ширина, pinBottom) —
  хранение пер-пользовательских патчей на бэке.

## 4. Тесты

Фронт-приёмники покрыты юнитами (`layout-props.test.tsx`,
`resolve-stack-gap.test.ts`); визуальная регрессия — `npm run test:visual`
(эталоны фиксируют текущий канон). Изменение семантики пропа = осознанное
обновление эталонов в том же PR.
