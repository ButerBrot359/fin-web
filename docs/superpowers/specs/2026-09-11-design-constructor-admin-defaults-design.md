# Конструктор дизайна Ф5 — админ-дефолты формы

Дата: 2026-09-11. Статус: РЕАЛИЗОВАНО 11.09, e2e на локальном стенде пройден
(подпись безымянному полю через админ-диалог; слои: личный патч поверх дефолта,
«Сбросить» пользователя возвращает к дефолту; PUT/DELETE дефолтов без
админ-роли — 403).
Родитель: `2026-09-10-design-constructor-architecture-design.md` §Ф5.

## Идея (решение владельца 10–11.09)

Ф5 — НЕ отдельный структурный редактор: админ настраивает форму ТЕМ ЖЕ
диалогом «Изменить форму», но сохраняет **дефолт для всех пользователей**.
Слои зафиксированы Ф1: базовый конфиг → **дефолт админа** → личный патч
пользователя; «Сбросить» у пользователя удаляет только его слой и
возвращает админский дефолт.

## Бэк (webbuh)

- Таблица `default_view_settings` (`screen_key` UNIQUE, `patch_json` JSONB) —
  один дефолт на экран, без привязки к пользователю.
- `GET/PUT/DELETE /api/view-settings-defaults/{screenKey}`; GET доступен всем
  аутентифицированным (диалог админа читает свой сид), PUT/DELETE — только
  административным ролям (`UserFullRightsResolver.hasFullRights`: «ПолныеПрава»,
  «АдминистраторСистемы»).
- Наложение в `UserViewSettingsAdvice`: дефолт и юзер-патч СЛИВАЮТСЯ по
  (nodeId, prop) — дефолт базой, юзер поверх — и applier вызывается один раз
  (его индекс по nodeId «последний выигрывает целиком», два вызова подряд
  потеряли бы дефолтный order при юзерском colSpan на той же ноде).
  `overrideSetProp` работает по слитому списку.
- Словарь пропов v2: + `label` (строка 1..256 после trim) — подписи
  безымянных полей, боль владельца («поля просто пустые без тайтла»).
  Разрешён обоим слоям: пользователь, переименовавший поле у себя, ничего
  не ломает.
- Команда «Изменить форму для всех» (`view.customizeFormDefault`,
  `mi.more.customizeFormDefault`) — эмитится в «Ещё» ТОЛЬКО админу
  (проверка в `CommandBarComposer.build`, стандартная группа остаётся static).

## Фронт (fin-web)

- `dispatch` перехватывает `view.customizeFormDefault` как вторую клиентскую
  команду контракта — открывает ТОТ ЖЕ диалог в режиме `default`.
- Режим `default` диалога: читает/пишет `/api/view-settings-defaults`,
  предупреждение «настройка применится всем пользователям», кнопка
  «Сбросить» удаляет дефолт экрана.
- Поле «Подпись» в режиме default для выбранного элемента → `props.label`
  (пустое = не переопределять). В пользовательском режиме подписи нет.
- Сид админского диалога — то же дерево с провода. Дерево уже несёт
  наложенные дефолты; собственный слой админа приходит из GET дефолтов.
  ВАЖНО: у админа может существовать И личный патч — при редактировании
  дефолта его личный слой в сид не подмешивается (диалог строит зоны от
  дерева, но решения сохраняет в дефолт целиком — WYSIWYG админа под его
  личным патчем принят как ограничение v1; чистая картина — снять личные
  настройки перед настройкой дефолта).
