# Конструктор дизайна: грид-модель шапки формы (v1)

Дата: 2026-09-11. Статус: черновик на согласование владельцу.
Продолжает `2026-09-10-design-constructor-architecture-design.md` (Ф4) и
закладывает фундамент Ф5 (админ-конструктор). Бэк-зеркало — раздел «Грид»
в `webbuh/docs/project/sdui/2026-09-10-design-constructor-back-spec.md`.

## 0. Зачем

Стек-модель шапки (`HSTACK(колонка, колонка)`) упёрлась в предел
пользовательской настройки (живые замечания владельца 11.09):

- порядок существует только внутри родителя → элемент нельзя поставить
  «куда угодно», только двигать в своей мини-группе;
- у стека нет единицы пространства → ширина выражалась пикселями или
  абстрактными ступенями, непонятными пользователю.

Решение: шапка объектной формы становится **одной GRID-нодой** — у всех
элементов один родитель, позиция и ширина выражаются единицами сетки.

## 1. Модель

- **Сетка: 24 единицы** на строку. Ступень пользователя — «доля строки»:
  ⅛ (span 3), ¼ (6), ⅜ (9), ½ (12), ¾ (18), 1 (24) — владелец явно просил
  «половину четверти», отсюда 24, а не 12. Админ (Ф5) сможет задавать
  любой целый span 1–24; пользовательский UI показывает только доли.
- **Пропы ребёнка грида**:
  - `colSpan: number` — единицы сетки (1–24, кламп);
  - позиция — существующий проп `order` (общий поток сетки, слева-направо
    сверху-вниз). Отдельного gridIndex НЕ заводим: applier уже умеет
    сортировать детей по order.
- **Перенос строки** — автоматический (CSS grid auto-flow row): элемент,
  не влезающий в остаток строки, уходит на следующую. Явных «строк» в
  модели нет — только порядок и ширины.

## 2. Бэк: нормализация шапки

Composer шапки объектной формы отдаёт вместо `HSTACK(VSTACK, VSTACK)`
одну ноду `GRID` (`props.columns: 24`, `gap` по словарю) с плоским списком
детей. Конвертация существующих конфигов — автоматическая, на сборке:

- поле в колонке из двух → `colSpan: 12`;
- поле на всю ширину → `colSpan: 24`;
- HSTACK из N полей внутри колонки → каждому `12/N` (кламп к целому);
- порядок — интерливинг колонок по строкам (визуальный порядок исходной
  формы), id нод НЕ меняются;
- **дыры сетки**: если в строке исходника колонка пуста (поле без пары —
  «Назначение аванса»), конвертер вставляет невидимую SPACER-ячейку
  нужного span — иначе авто-поток подтянул бы следующий элемент и
  раскладка съехала бы против исходной. Спейсеры не редактируются и в
  превью не показываются; пользовательская перестановка их игнорирует
  (двигая элементы, юзер строит свой поток без дыр).

Критерий корректности конвертации: **визуальный bit-perfect** — эталоны
`npm run test:visual` без диффа при пустых патчах.

Словарь патча: добавляется `colSpan` (int, кламп 1–24). `order` уже есть.
`width` (px) остаётся для нод вне грида (панели), в гриде игнорируется.

Скоуп v1: ШАПКА объектных форм. Вкладки, ТЧ, подвал — как есть.

## 3. Фронт: рендер

`GRID`-нода → `display: grid; grid-template-columns: repeat(24, 1fr)`,
gap из словаря; ребёнок → `grid-column: span {colSpan}` (кламп, дефолт 24).
Деградация: нет `colSpan` → вся строка; старые стек-конфиги (другие зоны)
рендерятся как раньше.

## 4. Редактор («Изменить форму», v4)

Превью рендерит ту же 24-сетку. Управление — **drag-n-drop с первой
версии** (решение владельца):

- **перетаскивание плашки за тело** — перемещение: подсветка места
  вставки, бросок = новая позиция в потоке (пересчёт `order` всех детей
  грида 0..n);
- **перетаскивание за правую кромку** — ширина: тянется по ступеням
  ⅛/¼/⅜/½/¾/1 с прилипанием к линиям сетки;
- клик по плашке — выбор; панель под превью остаётся как запасной
  доступ (галочка «показывать», доля строки селектом) — это же
  клавиатурная доступность;
- скрытые — пунктиром, возвращаются галочкой.

Реализация DnD: нативный HTML5 drag-and-drop (без новой зависимости);
если упрёмся в его ограничения (touch) — dnd-kit отдельным решением.

## 5. Совместимость и связь с Ф5

- Патч тот же (`/api/view-settings`), формат не меняется — добавляется
  один проп. Экспорт/импорт работают без правок.
- Агент (Ф2) получает те же `colSpan`/`order` в словарь инструментов.
- Ф5: админ редактирует БАЗОВЫЙ конфиг этим же превью-редактором, у
  пользователя те же операции поверх — слои патчей уже зафиксированы
  (базовый → админский → пользовательский).
