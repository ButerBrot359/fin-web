# КадровоеПеремещение — ТЧ не распределены согласно выгрузке (SDUI)

Дата: 2026-08-10
Экран: `dev.qazyna.ai/modules/ZarplatiIKadri/document/KadrovoePeremeshchenie/new`
Эталон: 1С «Кадровое перемещение (создание)», выгрузка `КБП_ФормыДокументов_FormXML_1_0_1_633_2026_08_07`,
файл `Documents/КадровоеПеремещение/Forms/ФормаДокумента/Ext/Form.xml`
Зона: **бэкенд** (сборка view-дескриптора). Фронт правок не требует.
Сверено с реальным ответом `OPEN /api/view` (form-session `04e45225…`, «Кадровое перемещение
(создание)») и с эталонным дескриптором `БольничныйЛист DEMO00-00005` (§4.1).

## 1. Симптом

Обе табличные части (`Сотрудники`, `Начисления`) выводятся плоско, одна под другой, без вкладок.
В 1С это две страницы (вкладки) «Сотрудники» и «Начисления». Дополнительно у обеих ТЧ
не совпадает состав и группировка колонок.

## 2. Что должно быть по выгрузке

```
UsualGroup ГруппаШапка (в 1С визуально две колонки)
  ├ ГруппаШапкаЛево   : Номер + Дата, Организация, Должность (служебное поле формы,
  │                     DataPath = ДолжностьСписок — реквизита документа за ним нет)
  └ ГруппаШапкаПраво  : ПодразделениеОрганизацииСтарое, ПодразделениеОрганизацииНовое,
                        ИндексацияЗаработкаСКоэффициентом (флажок)
Pages «Страницы»
  ├ Page ГруппаСотрудники  (заголовок «Сотрудники»)  → Table Сотрудники
  └ Page ГруппаНачисления  (заголовок «Начисления»)  → Table Начисления
UsualGroup ГруппаПодвал : Комментарий, Ответственный
```

Готовый эталон раскладки узлов — `2026-08-10-kadrovoe-peremeshchenie-expected-layout.json`
(рядом с этим файлом): та же структура на реальных `id` узлов из текущего OPEN, меняется
только расположение. Кратко:

```json
{ "type": "VSTACK", "children": [
  { "type": "HSTACK", "children": [ /* левая колонка шапки */, /* правая колонка шапки */ ] },
  { "type": "TABS", "children": [
    { "type": "TAB", "props": { "title": "Сотрудники" }, "children": [ { "type": "TABLE", ... } ] },
    { "type": "TAB", "props": { "title": "Начисления" }, "children": [ { "type": "TABLE", ... } ] }
  ] },
  { "type": "HSTACK", "children": [ /* Комментарий */, /* Ответственный */ ] }
] }
```

## 3. Что приходит по факту

```
PAGE
├ TOOLBAR commandBar  (Провести и закрыть / Записать / Провести / Дт-Кт / связанные /
│                      Заполнить (ПК) / Заполнить по стажу / Печать / Отчеты / Ещё)
└ VSTACK content
  ├ GROUP «Основное» : Organizatsiya, PodrazdelenieOrganizatsiiStaroe,
  │                    PodrazdelenieOrganizatsiiNovoe, IndeksatsiyaZarabotkaSKoeffitsientom
  ├ GROUP «Прочее»   : Kommentariy, Otvetstvennyy, Data, Nomer, DokumentOsnovanie
  ├ TABLE Sotrudniki   (11 колонок)
  └ TABLE Nachisleniya (23 колонки)
```

Групп «Основное» / «Прочее» в выгрузке нет вообще — шапка собрана по generic-схеме
в один столбец, ТЧ приклеены следом без `TABS`. Подвал (`ГруппаПодвал`) как блок тоже
потерян: `Комментарий` и `Ответственный` уехали в «Прочее» вместе с `Номер`/`Дата`.

Отдельно: поля `DokumentOsnovanie` (`targetTypeCode: "Tarifikatsiya"`) на форме 1С **нет**
вовсе — в `Form.xml` строка `ДокументОснование` не встречается ни разу.

Хорошая новость: команды формы `ЗаполнитьПК` и `ЗаполнитьПоСтажу` на месте, в главной
командной панели (§7 закрыт).

## 4. Корневая причина

Дескриптор ТЧ собирается **из метаданных табличной части (реквизитов объекта)**, а не из
элементов формы выгрузки. Три независимых доказательства:

1. **Набор колонок = список реквизитов ТЧ.** Для `Сотрудники` в вебе ровно 11 колонок —
   это в точности `Сотрудники` из листа «Реквизиты ТЧ (метаданные)» (минус служебные
   `ФизическоеЛицо`, `ПриказБГУ`).
2. **Есть колонки, которых нет на форме 1С:** `Размер предыдущий`,
   `Программа на разделение БГУ`, `Доля разделения БГУ` — существуют только в метаданных ТЧ.
3. **Нет колонок, которые есть только на форме.** Все `*Стар` — это `AdditionalColumns`
   формы (`<Attribute name="Объект"><Columns><AdditionalColumns table="Объект.Сотрудники">`),
   а не реквизиты ТЧ, поэтому при сборке по метаданным они теряются.

Следствия: нет `Pages` → нет вкладок; нет `ColumnGroup` → нет двухстрочной шапки;
теряются доп. колонки формы; порядок колонок — метаданный, а не формы.

### 4.1 Контрольный пример: БольничныйЛист (OPEN уже отдаёт TABS)

Дескриптор `БольничныйЛист DEMO00-00005` показывает, что **механика `TABS`/`TAB` на бэке
уже есть** — `tabs.main` с четырьмя `TAB`. Значит у `КадровоеПеремещение` дело не в
отсутствии возможности, а в том, что документ не переведён на сборку по выгрузке.

Но и в БольничномЛисте расхождения с выгрузкой те же по природе:

| Что | По выгрузке | В дескрипторе |
|---|---|---|
| Страницы | 5: **Условия**, Сотрудники, Начисления сотрудника, Средний заработок, Индексация | 4 таба — страница «Условия» потеряна, её 14 полей вылиты в шапку (`col.headerLeft` / `col.headerRight`) |
| Порядок табов | … Средний заработок, Индексация | … **Индексация, Средний заработок** (переставлены) |
| `ГруппаНомерДата` (`Group=AlwaysHorizontal`) | Номер + Дата в строку | оба поля в столбец `col.headerLeft` |
| Кнопка `ВыбратьПериод` | на форме, рядом с полями периода | уехала в меню «Ещё» (`mi.more.vybratPeriodBolnichnyyList`) |
| `КоличествоДней` | есть на форме | **нет в дескрипторе** |
| `field.prikaz`, `field.sredniyZarabotokSotrudnika` | **нет на форме БЛ** | есть в дескрипторе |
| `ColumnGroup` | 4 группы в СреднийЗаработок, 2 в Сотрудники, 1 в Начисления сотрудника | нет ни одной |

Колонки ТЧ — снова метаданные, а не форма:

- **Сотрудники.** Форма: № строки, [Сотрудник, ВидЗанятости], [ПодразделениеОрганизации,
  Должность], ВидНачисления. Дескриптор: Сотрудник, ФизическоеЛицо, Приказ, Состояние,
  ВидНачисления. Потеряны `ВидЗанятости`, `ПодразделениеОрганизации`, `Должность`, № строки;
  лишние `ФизическоеЛицо`, `Приказ`, `Состояние`.
- **НачисленияСотрудника.** Потеряны `КоэффициентИндексации`, `Сумма`, `ФКР`, `Специфика`;
  лишнее `ФизическоеЛицо`; вместо `Сумма` пришёл `Razmer`.
- **Индексация.** Лишний `Сотрудник`; колонка `Indeksatsiya` внутри ТЧ `Indeksatsiya`
  приехала с `"dataType": "TABLE", "cellWidget": "TABLE"` — таблица внутри ячейки таблицы,
  на форме это обычное числовое поле. Отдельный дефект.
- **СреднийЗаработок.** Состав близок, но плоско, без 4 групп; лишние `ФизическоеЛицо`,
  `Приказ`; `Сумма` формы приехала как `Rezultat`.

Порядок — как на форме 1С. `†` — `AdditionalColumns` формы (не реквизит ТЧ).

| # | Группа колонок (ColumnGroup) | Колонки | Есть в вебе |

| 2 | Сотрудники группа таб | Сотрудник / Табельный номер † | Сотрудник — да, Табельный номер — **нет** |
| 3 | Сотрудники группа перевод | Номер приказа / Подразделение новое | да, но вне группы |
| 4 | Сотрудники группа вид занятости | Вид занятости стар † / Вид занятости | только «Вид занятости» |
| 5 | Сотрудники группа должность | Должность стар † / Должность | только «Должность» |
| 6 | Сотрудники группа вид деятельности | Вид деятельности сотрудника стар † / Вид деятельности сотрудника | только новое |
| 7 | Сотрудники группа воинское звание | Воинское звание стар † / Воинское звание | только новое |
| 8 | Сотрудники группа категория | Категория стар † / Категория-разряд | только новое |
| 9 | Сотрудники группа вид стажа | Вид стажа стар † / Вид стажа | только новое |
| 10 | Сотрудники группа гарафи работы | График рабочего времени стар † / График работы | только новое |
| 11 | Сотрудники группа приказ | Дата трудового договора † / Номер трудового договора † | **нет обеих** |
| 12 | — | Основание | **нет** |
| 13 | — | Приказ (реквизит `ПриказСтар`) | да |

Итого в ТЧ «Сотрудники» не хватает 12 колонок; 10 групп колонок отсутствуют как понятие.

Фактические 11 колонок дескриптора (`table.sotrudniki`): `Sotrudnik`,
`PodrazdelenieOrganizatsii`, `Dolzhnost`, `VidDeyatelnostiSotrudnika`, `VidZanyatosti`,
`VidStazha`, `VoinskoeZvanie`, `Kategoriya`, `GrafikRabochegoVremeni`, `Prikaz`,
`NomerPrikaza` — один в один список реквизитов ТЧ из метаданных, минус служебные
`FizicheskoeLitso` и `PrikazBGU`.

Дополнительно в этих колонках сломаны типы:

- `col.dolzhnost` — `cellWidget: "REFERENCE_FIELD"`, `dataType: "DICTIONARY"`,
  но `domain: "STRING"` и **нет** `targetTypeCode`/`optionsSource`. Ссылочная ячейка
  без источника: подбор не откроется. По метаданным тип —
  `Справочник.КлассификаторДолжностей`.
- `col.prikaz` — `cellWidget: "REFERENCE_FIELD"`, `dataType: "OBJECT"`, без
  `allowedTypes`/`optionsSource`. По метаданным тип составной
  (`Документ.ПриемНаРаботуСписком | Документ.ПриемНаРаботу`) → должен быть `OBJECT_FIELD`
  с двумя `allowedTypes`, как это сделано у БЛ для `ФизическоеЛицо`.
- `col.sotrudnik` и `col.podrazdelenieOrganizatsii` приходят с `enabled: false` на новом
  документе (и `patches` это подтверждают для полей шапки) — ключевые колонки ТЧ
  нередактируемы, пока не выбрана организация. Проверить, что это осознанное поведение,
  а не побочный эффект пустого `Organizatsiya`.

Дескриптор отдаёт **23 колонки** — весь список реквизитов ТЧ из метаданных, целиком.
На форме 1С их 16 (в 6 группах). Лишних 9:

| `ПодборСотрудников` | ТЧ Сотрудники | **нет** — ни в `tableCommands` у `table.sotrudniki`, ни в тулбаре |
| `РассчитатьОклад` | ТЧ Начисления | есть (`table.rasschitatOklad:Nachisleniya`) |

не читает вовсе (`grep allowRaschetOklada src` → пусто) — кнопка живёт через
`tableCommands`. Мёртвый проп, можно убрать.

## 8. Фронт готов, правок не требует

- `TABS` / `TAB` зарегистрированы: `src/features/sdui/lib/component-registry.ts:58-59`,
  реализация — `src/features/sdui/ui/nodes/layout/tabs-node.tsx`, `tab-node.tsx`
  (MUI-табы, ленивое переключение панелей, поддержка `props.visible`).
- `COLUMN_GROUP` зарегистрирован там же (`component-registry.ts:77`),
  реализация — `src/features/sdui/ui/nodes/composite/column-group-node.tsx`.
- Дерево рендерится как пришло, без перестановок:
  `src/features/sdui/ui/sdui-screen.tsx:212` → `src/features/sdui/ui/node-renderer.tsx:12`.
- Рамки «Основное»/«Прочее» на скриншоте — это `GROUP`
  (`src/features/sdui/ui/nodes/layout/group-node.tsx:20-33`), т.е. ровно то, что прислал сервер.
- Подтверждено на практике: дескриптор `БольничныйЛист` с `tabs.main` рендерится вкладками
  без правок фронта.

Единственное, что фронт не умеет, — `TABLE_COLUMN` с `cellWidget: "TABLE"`
(колонка `Indeksatsiya` в ТЧ `Indeksatsiya` у БЛ): в `table-cell-editor.tsx:251` это
уходит в `default` и рисуется как нередактируемый текст значения. Чинить надо на бэке —
на форме 1С это обычное числовое поле.

## 9. Масштаб

По всей выгрузке: 89 форм документов, у 52 есть `Pages`, у **47** табличные части лежат
внутри страниц. Т.е. дефект системный, а не про один документ. Самые чувствительные:
`НачислениеЗарплатыСотрудникам` (15 ТЧ по вкладкам), `ЭСФ` (21 страница),
`БольничныйЛист` и `Отпуск` (по 4 ТЧ), `ПоступлениеОтКонтрагента` и `СписаниеОС` (по 4-5 ТЧ),
`АвансовыйОтчет`, `ВыбытиеТМЗ`, `ПеремещениеТМЗ`, `ИнвентаризацияОС`.

Отдельно: у `РегистрацияБухгалтерскихОпераций`, `РегистрацияЗаявленийПоВычетамИПН`,
`ЭлектронноеПисьмоИсходящее` таблицы в выгрузке действительно вне страниц — там плоский
рендер корректен.

## 10. Что сделать бэкенду

0. У `КадровоеПеремещение` включить сборку страниц так же, как это уже сделано
   у `БольничныйЛист` (там `TABS`/`TAB` отдаются — см. §4.1).
1. Переносить **все** `Pages` → `TABS`/`TAB` c заголовком из `<Title>` страницы, включая
   страницы без ТЧ (у БЛ страница «Условия» сейчас растворяется в шапке), и сохранять
   порядок страниц выгрузки.
2. Собирать состав и порядок колонок ТЧ по `ChildItems` таблицы формы, а не по метаданным ТЧ.
3. Поддержать `AdditionalColumns` формы (`*Стар`, `ТабельныйНомер`, `Дата/НомерТрудовогоДоговора`,
   `Должность` в Начислениях) — как readonly-колонки, заполняемые на сервере.
4. Переносить `ColumnGroup` → `COLUMN_GROUP` (по умолчанию вертикальная группировка —
   двухстрочная шапка, как в 1С).
5. Шапку собирать по `ГруппаШапкаЛево` / `ГруппаШапкаПраво`, а не по generic
   «Основное/Прочее»; подвал (`Комментарий`, `Ответственный`) вернуть отдельным блоком внизу.
6. `ПодборСотрудников` привязать к командной панели ТЧ «Сотрудники».
7. Не показывать служебные реквизиты ТЧ (`DannyeIzmeneny`, `FizicheskoeLitso`, `PrikazBGU`,
   `*NaRazdelenieBGU`), которых нет на форме.
8. Починить типы колонок: `col.dolzhnost` (ссылка без `targetTypeCode`/`optionsSource`),
   `col.prikaz` (составной тип → `OBJECT_FIELD` + `allowedTypes`), `col.prikazBGU`
   (`STRING` под `REFERENCE_FIELD`).
9. Убрать поле `DokumentOsnovanie` — на форме 1С его нет.
10. Убрать мёртвый `props.allowRaschetOklada`.
