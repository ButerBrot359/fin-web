# Визуальная регрессия

- Эталоны рендерятся на macOS (соглашение до появления CI); на других ОС
  тесты не гонять — diff будет ложным.
- `npm run test:visual` — прогон; `npm run test:visual:update` — осознанное
  обновление эталонов (только вместе с визуальным изменением в том же PR).
- Сеть замокана целиком: фикстуры в `fixtures/`, шрифты в `assets/`.
- Фикстуры сняты с dev-api 03.09.2026 живой сессией (тела ответов, без
  токенов); файл = экран, внутри карта «ключ mockApi → ответ». Ключи
  `POST /api/view` различаются по `action.type` и дискриминатору `@`
  (`layoutCode` либо `route`), значение `{ __status, __body }` задаёт
  не-200 ответ (легаси-двери = 422). Правки поверх снятого (out-of-band):
  в `osv-tree.json` state OPEN заполнен датами августа-2026 (стендовая
  форма стартует пустой), в `kartochka-ledger.json` state OPEN заполнен параметрами (счёт 1010, август-2026), даты в COMMAND-ответе
  исправлены на август-2026 (глюк ввода дат на стенде), run снят прямым
  запросом с теми же параметрами.
- Запуск перед мержем в dev обязателен (наравне с build).
- Смоук-эталоны и эталоны экранов создаются test:visual:update; правило:
  обновление эталонов только вместе с осознанным визуальным изменением в
  том же PR.

Дополнено при Task 10 (скриншот-спеки восьми опорных экранов):

- Спеки лежат в `tests/visual/screens-*.spec.ts` (не в одном `screens.spec.ts`
  — разбиты по смыслу: `screens-cards` — экраны без доп. сетевых шагов после
  OPEN, `screens-legacy-and-reports` — легаси-дверь и отчёты с клавишей
  «Сформировать», `screens-states` — два состояния поверх этих же экранов).
  Фикстуры читаются хелпером `tests/visual/helpers/load-fixture.ts`
  (`readFileSync` + `JSON.parse`, не json-импорт — не спорит с tsconfig).
- В `otpusk-card.json` добавлен ключ `POST /api/view#EVENT` (без `@`-
  дискриминатора, формSessionId/revision как в OPEN-ответе того же экрана,
  `formDirty: true`). Он нужен тесту `unsaved-dialog.png`: dirty-флаг
  вкладки — серверный (SCRUM-288 §2.5), а не локальный react-hook-form, и
  без ответа с `formDirty: true` на fieldEvent-запрос (посылается на blur
  текстового поля) диалог «Сохранить изменения?» не появляется.
- В том же тесте текст вводится в поле «Основание» (вкладка «Условия»), а
  не в «Комментарий» из примера в брифе Task 10: у «Комментарий» в снятой
  фикстуре `"maxLength": 0`, который `TextFieldNode` прокидывает в HTML как
  `maxlength="0"` — браузер блокирует любой ввод в это поле целиком. Это
  особенность уже снятых данных/рендера, а не тестовой инфраструктуры;
  фронт `src/` не менялся.
